Privacy Policy — Central do Moraes

Effective date: October 20, 2026 · Última atualização: 20/10/2026 · Versão em português abaixo.

Central do Moraes ("the app") is a personal dashboard built and used by a single individual, João Gabriel Moraes da Silva ("the owner"), in Londrina/PR, Brazil. It is not offered to the public. The only Google account it accesses is the owner's own account. This policy explains what data the app accesses through Google APIs, how it is used, stored, shared, retained and deleted.

1. Data accessed from Google

The app uses the Google Health API with read-only access. It requests only these OAuth scopes:

ScopeData read
googlehealth.sleep.readonlySleep sessions: start and end time, minutes asleep, minutes awake, sleep stages.
googlehealth.activity_and_fitness.readonlyDaily step count and exercise sessions (type, start time, duration, calories, average heart rate).
googlehealth.health_metrics_and_measurements.readonlyDaily resting heart rate, daily heart rate variability, VO2 max and body weight.

The app does not access the user's name, email, contacts, location, Gmail, Drive or any other Google data. It never writes, edits or deletes anything in the Google account.

2. How the data is used

The data is used for one purpose only: to show the owner his own sleep, recovery and training information in his personal dashboard (for example, a daily readiness indicator computed from heart rate variability, resting heart rate and sleep, and a training log). The data is not used for advertising, profiling, credit or lending decisions, or to train any machine-learning or AI model, and it is not sold.

3. How the data is collected and stored

  • A scheduled job (GitHub Actions in the owner's repository) uses a refresh token stored as an encrypted repository secret to read the last 40 days of the data listed above.
  • Before leaving the job, the data is encrypted with AES-256-GCM, and the AES key is encrypted with an RSA public key. Only the owner's app holds the private key. The encrypted file contains no readable health data.
  • The owner's app downloads the encrypted file, decrypts it on the device, and saves the result in the app's private database, which only the owner can access.
  • Each new sync overwrites the previous encrypted file. No copy of the readable data is kept in the repository.

4. Sharing

The data is not shared with, transferred to, or sold to any third party. It is not shown to anyone other than the owner. The only services involved in processing are GitHub (running the job and hosting the encrypted file) and the platform that hosts the owner's private dashboard. Neither receives the data in readable form, except that the dashboard platform stores the decrypted data in the owner's private database.

5. Google API Services User Data Policy — Limited Use

The app's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. In particular, data from Google APIs is used only to provide the dashboard features described above. It is not transferred to others except as needed to provide those features, to comply with law, or as part of a merger or acquisition. It is not used for advertising, and no human reads it except the owner.

6. Retention and deletion

  • The sync job reads only the last 40 days. The dashboard keeps up to 400 days of daily summaries so the owner can see trends.
  • The owner can delete all stored health data at any time by deleting the app's health records in its database and the encrypted file in the repository.
  • Access can be revoked at any time at myaccount.google.com/permissions. After revocation, no new data is read.

7. Security

OAuth credentials are kept only in GitHub encrypted secrets. Data in transit uses HTTPS and the encryption described in section 3. Access to the repository and the dashboard is limited to the owner.

8. Changes and contact

Changes to this policy are published on this page with a new effective date. Questions: jaumlive3@gmail.com.
